# US-04: Stories con Gherkin derivadas de una épica aprobada

**Épica**: EPIC-01
**Estado**: Aprobado
**Firmado por**: Kevin Barroso (firma transcrita por el Planner por autorización explícita en sesión)
**Fecha de firma**: 2026-09-06
**Prioridad**: P1
**Rol ejecutor**: Planner (`knowledge-x6e`)

Como PM quiero correr `/product-stories EPIC-xx` sobre un PRD aprobado y obtener un
archivo `docs/product/stories/EPIC-xx/US-xx.md` por story, con criterios de aceptación en
Gherkin, para que el spec, los tests y la validación de QA salgan del mismo texto.

## Criterios de aceptación

```gherkin
Feature: Stories con Gherkin

  Scenario: /product-stories exige PRD aprobado
    Given docs/product/PRD.md con Estado "Borrador"
    When el Planner corre /product-stories EPIC-01
    Then el comando se detiene sin escribir stories
    And informa que PRD.md necesita Estado "Aprobado"

  Scenario: Cada story sigue la plantilla
    Given un PRD aprobado con la épica EPIC-01
    When el Planner corre /product-stories EPIC-01
    Then existe docs/product/stories/EPIC-01/US-NN.md por cada story de la épica
    And cada archivo tiene encabezado con Épica, Estado, Prioridad y Rol ejecutor
    And la frase "Como <rol> quiero <acción> para <valor>"
    And un bloque gherkin con al menos un Scenario Given/When/Then
    And una sección Notas / dependencias

  Scenario: La story es la fuente de las user stories del spec
    Given una story US-03 con tres escenarios Gherkin
    When el Planner corre /speckit-specify para su épica
    Then spec.md tiene una sección "User Story 3" con link a US-03.md
    And sus Acceptance Scenarios son los mismos tres escenarios
    And /speckit-analyze reporta divergencia si los escenarios difieren

  Scenario: QA valida contra el Gherkin
    Given un PR que referencia US-03
    When el QA Agent revisa el PR
    Then su comentario lista cada Scenario de US-03 con resultado pasa/falla
```

## Notas / dependencias

- Depende de US-03 (PRD con épicas).
- La validación de QA por PR se implementa completa en EPIC-02; acá solo se documenta la
  regla en `agents/qa/AGENTS.md`.
