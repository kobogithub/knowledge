# US-02: Discovery con rol Analyst produce PROJECT.md

**Épica**: EPIC-01
**Estado**: Aprobado
**Firmado por**: Kevin Barroso (firma transcrita por el Planner por autorización explícita en sesión)
**Fecha de firma**: 2026-09-06
**Prioridad**: P1
**Rol ejecutor**: Planner (`knowledge-x6e`) define el rol; Docs Writer (`knowledge-doc`) escribe plantillas

Como PM quiero correr `/product-discovery` con la transcripción de la reunión con el
cliente y obtener un `docs/product/PROJECT.md` en borrador, para que el relevamiento quede
en el repo con preguntas abiertas explícitas en lugar de supuestos inventados.

## Criterios de aceptación

```gherkin
Feature: Discovery agentificado

  Scenario: Existe el rol Analyst instalable con kn
    Given el directorio agents/ del repo
    When se lista agents/analyst/AGENTS.md
    Then tiene frontmatter con name "analyst", id_prefix, model y description
    And AGENTS.md raíz lo lista en la tabla de roles con su ID knowledge-<prefix>
    And kn.toml lo declara bajo [agents.analyst]

  Scenario: /product-discovery genera PROJECT.md desde un input guardado
    Given un archivo en docs/product/discovery/<fecha>-<tema>.md con la transcripción
    When el Analyst corre /product-discovery apuntando a ese archivo
    Then se crea docs/product/PROJECT.md con las secciones de la plantilla en orden
    And el encabezado tiene Estado "Borrador", Firmado por "—" y link al input
    And todo dato que no está en el input aparece en "Preguntas abiertas", no como hecho

  Scenario: El Analyst no rellena huecos
    Given un input que no menciona presupuesto ni fecha límite
    When se genera PROJECT.md
    Then la sección Restricciones no inventa cifras ni fechas
    And Preguntas abiertas contiene una pregunta por cada dato faltante

  Scenario: La plantilla existe para reutilizarla en otros proyectos
    Given .specify/templates/ o docs/product/
    When se busca la plantilla de PROJECT.md
    Then existe una plantilla con placeholders y las diez secciones de la guía
```
